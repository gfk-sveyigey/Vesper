# Aether / Emby 后台视频恢复

Aether 7.70.0 的 `needsForegroundVideoRestore` 表示后台释放了视频管线；原播放器壳仍在，不能直接 `play()` 或用 seek 代替重建。
App 通过桥接快照的 `requiresForegroundReload` 消费此状态。此状态不意味着所有暂停画中画都会释放：引擎也检查 PiP 与后台播放策略，窗口关闭的实际原因仍需设备日志确认。

- 桥接层保留最近有效的进度、时长和轨道选择，避免管线释放后空快照覆盖它们。
- 前台通知与首次恢复轮询均检查该状态，兼容生命周期通知先后顺序。
- 从保留进度重新解析 Emby 播放资源，重新创建播放器；前台恢复保持暂停。
- 用户主动点击播放时，如此状态仍未处理，则重建并继续播放。
- 恢复期间不接受旧管线的 seek；沿用现有加载错误展示，不静默吞掉重建错误。
- 不通过静音音频、无限后台任务或延长引擎宽限期强行保活，不承诺暂停 PiP 永远不关闭。

## 真机验证（尚未执行）

1. Aether 播放 Emby 视频，启用 PiP，后台播放数分钟，确认正常推进。
2. 后台 PiP 暂停并等待，若窗口消失，回前台后应保留进度并重建，不能自动出声。
3. 点击继续，检查画面、音频、字幕选择、倍速及进度；分别覆盖原生/软件解码。
4. 暂停期间切换网络或使播放 URL 失效；重新解析失败时应显示错误，可重试。
5. 快速前后台切换、停止/更换视频时不允许旧恢复任务覆盖新视频。
6. 手动关闭 PiP、系统音频中断、媒体服务重置分别记录日志，不能一概当成内存回收。

## 后台音频模式与自动 PiP

音频模式不应自动出现 PiP。Aether 桥接仅在以下情况下创建/保留系统 PiP 控制器：
- 配置明确启用自动 PiP（后台模式为画中画）；
- 用户主动点击手动 PiP，调用 `preparePiP()` 后等待 AVKit 就绪，再开始 PiP。

从自动 PiP 切回音频模式时，停止旧控制器、清空内容源和引擎 PiP 标记。手动 PiP 结束或启动失败后撤销手动请求。
不再为轮询画中画可用状态而在音频模式下持续创建控制器。手动按钮的初步可用性根据引擎输出层判断，真正开始前最多等待 3 秒确认系统控制器就绪；等待期间更换视频或进入不允许 PiP 的后台会取消请求。

真机还需验证：音频/画中画模式冷启动、播放中切换模式、原生与软件输出、音频模式手动打开/关闭 PiP。此改动尚不能证明旧版本自动弹窗的底层触发时序。
