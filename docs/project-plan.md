# Vesper 项目计划

本计划按依赖和风险排序，不设未经团队容量确认的日历日期。每阶段完成其退出条件后再进入依赖它的阶段。仓库已建立阶段一的 SwiftUI 导航原型源码与 原生 Xcode 工程，Apple 编译已通过 GitHub Actions，阶段一设备交互验收已由用户确认完成，当前推进阶段二。

## 产品基线

- 主导航四个标签：媒体、来源、记录、设置。
- 媒体页只显示当前选定的单一来源；来源页负责配置和切换来源。
- 媒体页采用电影幕墙；记录页负责最近播放、观看进度和历史；设置页负责应用和常用播放器偏好及服务连接管理。
- 支持本地与在线媒体。IMDb/Trakt 的数据/同步职责需在接入前分别明确。
- 导航栏和标签栏透明；使用原生 TabView 标签栏，默认隐藏，由多任务按钮切换显示，点击内容区域收起。
- 播放呈现支持全屏、标题/导航区域紧凑播放条、系统 PiP；不做 App 内可拖动小窗。PiP 控制应覆盖暂停、继续和可用的跳转命令。
- 完整全屏播放控制 UI 暂不作为首版视觉设计交付；播放器会话、紧凑播放和 PiP 的状态切换属于首版需求。

## 阶段 0：开工决策与可行性核验

- [ ] 确定首发平台、deployment target、Xcode/Swift 基线和设备测试矩阵。
- [ ] 核实 KSPlayer 版本、选择候选后端，并审查 GPL/商业授权与目标分发方式的兼容性。
- [ ] 明确首版本地来源入口及至少一种在线来源/协议，列出鉴权、网络失败和权限生命周期要求。
- [ ] 验证候选 KSPlayer 后端在目标 OS 上的 PiP、视频画面交接、暂停/继续、跳转和 Now Playing 能力。
- [ ] 明确 IMDb 数据/API 授权与归因路径；明确 Trakt OAuth、同步对象、双向/单向规则和冲突处理。
- [ ] 确认媒体模型的电影/剧集/集数范围、文件与网络资源识别方式，以及资料匹配的人工纠正流程。

**退出条件：** 上述决策有负责人和结论；许可可行；本地、在线及 PiP 各有明确技术路径。若 PiP 或服务对接受限，先调整范围并更新规范，不带着假设进入实现。

- [x] 建立四个标签的应用结构与路由状态。
- [x] 实现透明导航/标签栏内容延伸与安全区处理。
- [x] 验证原生 TabView、返回、系统焦点、VoiceOver 与键盘行为。
- [x] 建立 Light/Dark Color Set、主题设置与基础原生组件样式。
- [x] 建立 App 内日志存储、分页、清理与完整文件分享；依用户要求移除所有已有诊断记录点。

## 阶段 2：来源模型与媒体页骨架

**状态：核心实现完成，编译及状态验证见本次提交。** 当前仅提供明确标识的演示来源；真实本地/网络接入、账号、播放在后续阶段实现。

- [x] 定义 `MediaSource`、来源能力、来源内媒体标识、可播放资源与媒体条目，区分媒体来源与外部服务。
- [x] 实现演示来源添加、状态配置、选择和删除，并持久化来源列表及当前选择。
- [x] 实现媒体页单来源加载、内容、空、错误与离线状态；支持重试和取消过期请求。
- [x] 建立 `SourceAdapter` 边界；视图不依赖文件系统、网络协议或 KSPlayer。
- [ ] 验证两个演示来源之间切换、重启恢复、失败隔离及快速切换无过期数据覆盖。

**退出条件：** 两个演示来源切换更新媒体内容但不强制切换当前标签；失败仅影响当前来源，其他来源可正常选取；状态验证通过。验证入口及运行方式见 [阶段二验证](phase-two-validation.md)。

## 阶段 3：本地来源与电影幕墙

- [ ] 按阶段 0 决策实现本地媒体选择/导入，正确维护系统授权和资源生命周期。
- [ ] 实现媒体识别、元数据基础模型和 poster wall 网格；缺封面、长标题、无元数据均有可用呈现。
- [ ] 实现媒体详情、搜索/筛选/排序（按首版确认的范围）。
- [ ] 验证动态字体、VoiceOver、横竖屏、窄宽窗口及目标输入方式。

**退出条件：** 用户能从本地来源浏览并打开支持的媒体；无效/失权资源有清楚状态；网格可访问且滚动性能达到设备验收标准。

## 阶段 4：在线来源与播放会话

- [ ] 实现阶段 0 选定的在线协议/来源及凭据安全存储、取消、超时和错误映射。
- [ ] 接入 KSPlayer adapter，建立单一播放会话所有权和状态事件映射。
- [ ] 从媒体页/详情启动播放，切换媒体和退出时正确释放/复用会话。
- [ ] 验证低带宽、断网、鉴权失败、快速切换和重复打开等情况。

**退出条件：** 所选本地与在线媒体均可通过统一播放流程启动；错误可恢复；无泄漏凭据、过期任务覆盖或重复播放器实例。

## 阶段 5：记录、设置与外部服务

- [ ] 实现最近播放、观看进度和历史记录，并明确记录保留/清除行为。
- [ ] 实现设置分组，只显示目标平台、KSPlayer 后端和当前媒体实际支持的选项。
- [ ] 实现 IMDb 资料匹配/查询（仅在 API、许可和归因路径核验通过后），支持多结果确认和用户纠正。
- [ ] 实现 Trakt OAuth 与首版确认的同步对象；设计离线队列、冲突处理、重新授权和断开账号行为。
- [ ] 区分 IMDb 元数据与 Trakt 观看/列表数据，不让外部服务覆盖用户本地原始信息。

**退出条件：** 历史/进度行为可预测；外部服务授权可撤销；匹配与同步失败不阻塞本地播放；隐私说明和服务归因齐备。

## 阶段 6：紧凑播放、PiP 与系统集成

- [ ] 实现全屏播放与标题/导航区域紧凑播放条的同会话转场、展开和关闭/停止语义。
- [ ] 接入系统 PiP，在支持的后端与 OS 上完成进入、退出、前后台和恢复路径。
- [ ] 配置 PiP/系统媒体控制的暂停、继续及当前媒体支持的跳转命令，统一播放进度和 Now Playing 信息。
- [ ] 验证 PiP 与紧凑播放条之间的切换、快速重复操作、锁屏/控制中心控制及通话/音频中断行为。
- [ ] 明确 PiP 不支持时的提示/回退；不以 App 内可拖动浮窗替代。

**退出条件：** 设备验证证明无重复播放器、无进度重置；PiP 控制与播放会话一致；所有失败和不支持路径有明确行为。

## 阶段 7：稳定性与首版验收

- [ ] 完成目标设备/模拟器矩阵的 build、单元测试、集成测试和 UI smoke tests。
- [ ] 验证导航、电影幕墙、来源切换、媒体打开、记录、服务连接、设置和 PiP 的关键流程。
- [ ] 检查性能、内存/播放资源释放、网络恢复、可访问性、隐私和许可声明。
- [ ] 清点未实现能力和限制，更新用户可见错误、隐私文档、许可 notices 及项目 README（仅在用户明确开始编写用户介绍时修改）。

**退出条件：** 阻断级缺陷清零；关键流程可重复通过；已知限制、许可与外部服务要求得到记录并经负责人确认。

## 首个工作切片

开始写业务代码前，先完成阶段 0 的平台、许可、来源和 PiP spike。其后首个可交付切片建议为：应用骨架 + 四标签导航原型 + mock 来源选择 + 单来源媒体页空/加载/错误状态。这样可以尽早验证导航约定与核心数据关系，再接真实来源和 KSPlayer。
